Тесты - фиксируют контракт приложения/модуля, защищая от неожилданностей в случе изменений.

Интеграциолнные тесты - проверяют что сценарий удачно сработал во всех компонентах системы и передал нужный ответ на нужные данные

Юнит тесты - проверяют что модуль верно реагирует на данные.

Редис для хранения сессий. 

Принцип минимального вмешательства (третье звено когда необходимо (сценарии, геттеры) )

Принцип третьего звена (сценарии, геттеры - это третье звено, только если исп 2 раза)

Вместо внедрения функций - передача результатов (уменьшает связность?)

Императивная оболочка, фукнциональное ядро 

Выбран функциональный стиль из-за простоты расширения:
1. не нужно джобавлять класс, только функцию (товар цена и цена по скиндке)
2. не нужно парится с интерфейсами (контрактами), все через функции
Через резалт проще обрабатывать ошиьбки - одна линия и один выход ошибки


Кратко причины выбора Result вместо исключений в Rust:

1. Явная обработка ошибок — компилятор требует обработать Result, ошибку нельзя случайно проигнорировать.
   (ошибки нельзя забыть обратотать)
2. Ошибки видны в типах — сигнатура fn foo() -> Result<T, E> сразу показывает, что функция может завершиться ошибкой.
3. Предсказуемый поток выполнения — нет скрытых переходов в catch; возможные точки выхода из функции явно обозначены (?).
4. Хорошая оптимизация — Result является обычным значением, без механизма раскрутки стека, как при исключениях.
5. Повышенная надежность — многие ошибки обнаруживаются на этапе компиляции, а не во время выполнения.
6. Разделение ошибок — ожидаемые ошибки (например, отсутствие файла) возвращаются через Result, а критические нарушения логики программы обрабатываются через panic!.

В чем отличие от исключений?

При использовании исключений возможность ошибки не входит в тип функции — компилятор не всегда может проверить, что ты ее учел.

При использовании Result возможность ошибки является частью типа, поэтому компилятор гарантирует, что ты не сможешь обращаться с ошибкой как с успешным результатом.

Поэтому формулировку пункта лучше сделать так:

try:
    p = fetch_permissions(PermissionsFilter(item_id="10")).unwrap()

    try:
        p = grant_for_group(p, "test-user", "write").unwrap()
        p = grant_for_other(p, "test-user", "write").unwrap()
    except:
        pass

    p = revoke_for_other(p, "test-user", "read").unwrap()
    p = revoke_for_group(p, "test-user", "read").unwrap()

    print(p)
except:
    raise

p = fetch_permissions(PermissionsFilter(item_id="10"))

p = (p
    .and_then(lambda p: grant_for_group(p, "test-user", "write"))
    .and_then(lambda p: grant_for_other(p, "test-user", "write"))
)

p.and_then(lambda p: revoke_for_other(p, "test-user", "read"))
p.and_then(lambda p: revoke_for_group(p, "test-user", "read"))

print(p.unwrap())
